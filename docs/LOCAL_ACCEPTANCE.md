# Personal Economy 本地验收入口

本轮完成五个主模块页面及已设计核心操作的前端代码，接入本机单用户后端。类型检查、静态检查和构建用于保证工程可运行；**未执行测试套件或逐页浏览器验收**，MySQL阶段只做必要连通与持久化检查，功能和视觉结果由用户验收。

## 启动

按 [MySQL本地启动说明](MYSQL_LOCAL.md)启动数据库，在根目录运行 `python3 scripts/backend-mysql.py`，另开终端进入 `frontend`，运行 `npm ci` 和 `npm run dev`。访问 `http://127.0.0.1:5173`。

默认 `dev/mysql` 模式使用MySQL。首次导入根 `data/workspace.json`，成功后数据库为主数据源，重启不覆盖；原文件和备份保留。API返回 `source: local-mysql`，首页行情仍为 `demo`。

这是本机固定用户模式，没有真实登录账户。API限制回环请求、Host及Origin；prod被阻止。这些限制不代替生产认证。首次导入、备份及显式旧文件模式见MySQL说明。

## 页面入口

| 模块 | 入口及子页面 |
|---|---|
| 首页 | `/`，周期选择、走势图节点选择、最近事件详情入口 |
| 成长中心 | `/growth/goals`、`/growth/tasks`、`/growth/events` |
| 成长表单 | `/growth/{goals,tasks,events}/new`；详情 `/{id}`；编辑 `/{id}/edit` |
| 操作结果 | 目标/待办 `/{id}/completed`；事件 `/{id}/saved` |
| 分类管理 | `/growth/categories`，自定义分类添加和停用 |
| 分析 | `/analytics`、`/analytics/chart`、`/analytics/breakdown` |
| 财务 | `/finance`、`/finance/records`、`/finance/records/new`、`/finance/assets` |
| 财务保存反馈 | `/finance/records/{id}/saved` |
| 我的 | `/profile`、`/profile/edit`、`/profile/settings` |
| 本地数据导出 | `/profile/data`：JSON备份页，作为数据管理菜单的工程验收入口；尚无完整对应Penpot页面 |
| 连接检查 | `/dev/connection` |

表单日期、月份、分类和关联目标使用原生控件实现实际输入与选择，弹出样式可能与 Penpot 示意不同。删除确认使用原生 modal dialog。加载中、请求失败、空列表及保存失败保留表单均有对应实现，但未逐项测试。

## 请按这些路径验收

1. 切换五个主导航，检查选中态和返回，确认表单/详情隐藏主导航。
2. 创建目标，编辑描述、日期和手动进度，返回详情查看保存结果。
3. 从目标详情添加关联待办，检查目标标题和关联详情。
4. 创建独立待办，完成、撤销完成、编辑及删除。
5. 确认待办完成不改变目标手动进度，也不改变行情指数。
6. 完成目标后选择“仅完成目标”，确认不会创建成长事件、不会自动把进度置100%。
7. 完成目标后选择“记录为成长事件”，检查来源目标，保存后应显示待评估。
8. 单独新增、编辑、筛选和删除成长事件；确认新事件进入首页最近列表，但不会凭空计算指数贡献。
9. 添加自定义分类并用于新事件；停用后检查历史记录名称保留，新增表单不再提供停用分类。
10. 检查分析页周期、历史图和分类统计；待评估事件单独标记，不能误读成0分。
11. 新增收入或支出，查看记录列表与本月统计；切换月份、类型并检查空状态。
12. 确认收入/支出不会自动修改手动资产快照。
13. 手动更新现金、其他资产及负债，检查净资产展示与保存反馈。
14. 修改昵称、简介和头像，再返回首页确认昵称同步。
15. 导出JSON，查看内容是否包括本地记录；不要把它当作Penpot源文件。
16. 重启后端，确认此前新建与修改的记录仍然存在。
17. 停止后端后尝试操作，确认错误可见、没有伪成功，表单内容保留；重启后重试。
18. 检查空标题、长文本、金额小数、日期和移动端键盘；在393×852、窄屏及短屏检查滚动与遮挡。

## 接口

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/api/v1/workspace` | 单用户工作区快照 |
| POST / PUT | `/api/v1/goals`、`/goals/{id}` | 创建/编辑目标 |
| POST | `/api/v1/goals/{id}/complete` | 仅更新完成状态和完成日期 |
| POST / PUT / DELETE | `/api/v1/tasks`、`/tasks/{id}` | 待办创建/编辑/删除 |
| PATCH | `/api/v1/tasks/{id}/status` | 完成或撤销完成 |
| POST / PUT / DELETE | `/api/v1/events`、`/events/{id}` | 事件创建/编辑/删除 |
| POST / DELETE | `/api/v1/categories`、`/categories/{id}` | 自定义分类新增/停用 |
| POST | `/api/v1/finance/records` | 记录收支 |
| PUT | `/api/v1/finance/assets` | 独立更新手动资产快照 |
| PUT | `/api/v1/profile` | 编辑资料，股票代码只读 |
| GET | `/api/v1/home` | 固定演示行情＋来自工作区的最近事件和昵称 |

写操作响应包含 `{ snapshot, affectedId }`，完成MySQL写事务后才报告成功；旧文件模式则完成原子文件替换。请求/返回对象位于 `dto` / `vo`，持久化适配器位于 `service/impl`。

## 明确未完成和待确认

- 真实注册登录、个人上市、密码修改和退出登录：设计流程不足，页面说明尚未接入，不伪装已登录。
- MySQL本机业务持久化已接入；生产认证及多用户隔离验收未完成，正式数据库评审仍需推进。
- 指数评分、权重、动能衰减、历史重算：未实现。新事件及编辑后的事件保持PENDING，固定演示走势图不会自动变化。
- 当前类别名称、财务输入分类和用户参考重要程度用于本机验收，开发schema只约束当前已使用的状态；不能当作最终分类体系、重要程度权重或已评审的正式数据模型。
- 演示种子只有实际存在的部分记录，统计数量、收支汇总可能不同于设计中的完整示例。分析分类合计也不等于完整行情累计变化。
- 目标更新日志尚无确认的数据设计，未伪造历史日志；目标删除、财务记录编辑/删除未提供完整设计，本轮未添加这些操作。
- 页面视觉、交互、错误恢复、无障碍、持久化与原有测试套件仍需用户实际验收；现有测试包含早期演示契约，随产品变化需复核。
