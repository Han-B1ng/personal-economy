# 首页查询接口（联调契约）

当前只实现本地开发用的只读演示适配器。行情保持固定演示值，昵称和最近事件读取当前工作区（dev/mysql为数据库，bootstrap为文件）；不具备真实账户认证或评分能力。

## 请求与环境

`GET /api/v1/home`，无请求体，无用户输入或周期参数。

在本机 `dev/mysql` 或显式 `bootstrap` 中提供，`prod` 禁用。服务绑定 `127.0.0.1`。MySQL下资料与最近事件读数据库，指数及历史仍明确标为demo。

前端默认通过 Vite `/api` 代理请求此接口。`VITE_HOME_DATA_SOURCE=demo` 可显式选择离线页面演示；连接失败不会自动切换数据源。

## 响应

使用公共信封 `{ code, message, data }`，成功为 `code: "OK"`。

| data 字段 | 传输类型 | 页面用途 | 当前来源 |
|---|---|---|---|
| source | 字符串，目前固定 `demo` | 明确演示数据边界 | 固定标记 |
| nickname | 字符串 | 股票身份区域的昵称 | 当前工作区资料 |
| stockCode | 字符串 | 股票代码 | 当前工作区资料 |
| index | JSON 数字 | 当前成长指数 | 演示值，后端 BigDecimal |
| change | JSON 数字 | 本期涨跌点数 | 演示值，后端 BigDecimal |
| changePercent | JSON 数字 | 本期涨跌百分数 | `3.36` 表示 `3.36%`，不是 `0.0336` |
| history | 按时间升序排列的数组 | 可选择历史节点与周期筛选 | 43个演示点 |
| history[].timestamp | JSON 整数 | 节点时间与横轴 | UTC Unix 毫秒；模拟采样时间 |
| history[].value | JSON 数字 | 节点指数与纵轴 | 演示值，后端 BigDecimal |
| recentEvents | 数组 | 最近成长事件 | 当前工作区按日期倒序最多三条事件 |
| recentEvents[].id | 字符串 | 列表 key 与详情入口 | 保留的业务ID，可进入对应事件详情 |
| recentEvents[].title | 字符串 | 事件标题 | 工作区事件标题 |
| recentEvents[].date | ISO 日期字符串 `YYYY-MM-DD` | 页面显示为 `YYYY.MM.DD` | 工作区事件日期；不做时区换日 |
| recentEvents[].categoryMark | 字符串 | 事件类别徽标 | 演示显示符号；不等于分类编码 |
| recentEvents[].contribution | JSON 数字或null | 展示模拟指数贡献 | 已有演示贡献或null（待评估），不据此确认权重或评分算法 |

数值与历史、事件由同一份快照响应提供，避免页面三个区域读取不同批次的演示数据。后端不会执行任何写操作。周期筛选暂在前端根据演示历史的最新时间处理，长周期不会补造不存在的历史。

## 状态处理

- 200：验证信封及字段，展示 `演示数据`。
- 404：当前 profile 没有提供查询接口。
- 405：不支持 POST 等写入方法。
- 500 或代理/网络故障：前端显示加载失败及重试，保留错误边界，不返回伪成功数据。
- 请求10秒未完成：前端取消请求并显示失败；新请求取消旧请求，过期响应不得覆盖最新状态。
- 无历史、无事件：分别显示对应空状态。开发预览 `/?preview=empty`、`/?preview=error` 仅作用于开发构建。

## 真实数据接入前需确认

以上字段已用于当前 UI 与联调，但不代表对应数据库字段和业务规则已获批准。

- 用户资料与个人股票字段复用既有评审稿；先确认身份认证和用户隔离方式，不能把演示昵称当已登录用户。
- 指数历史需要事件时间/记录时间、粒度、查询范围及长期历史的返回规模；物理表、索引和历史重算方式尚未实施。
- `change` / `changePercent` 的比较基准、初始值与更新规则待确认，目前是设计演示值。
- 最近事件需确认真实排序、数量与事件分类显示方式；贡献来源和待评估事件的显示方式待确认。
- 事件权重与动能衰减未实现；普通待办完成不会通过该查询接口推动指数变化。

确认后再增加真实查询适配器、审核数据库迁移并验证用户隔离。演示接口、真实查询、数据库持久化与指数计算应分别验收。
